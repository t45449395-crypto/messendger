# Чаты

Адаптивный браузерный мессенджер. Интерфейс размещается на GitHub Pages; Supabase предоставляет бесплатный гостевой вход, базу профилей и личные переписки в реальном времени.

## Подключение Supabase

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. Откройте **SQL Editor**, выполните содержимое `supabase/schema.sql`. Обновлённая схема переносит личные переписки на таблицу участников, добавляет группы, закрытый Storage-бакет для файлов, WebRTC-сигнализацию и таблицу статусов Premium. При обновлении существующего проекта сделайте резервную копию базы и проверьте сообщения SQL Editor на ошибки.
3. В **Authentication → Sign In / Providers** включите **Allow anonymous sign-ins** (гостевой вход). Телефон, SMS-провайдер и email не нужны. Вход не оплачивается отдельно; ограничения бесплатного плана Supabase остаются в силе.
4. В **Project Settings → API** скопируйте Project URL и publishable key (`sb_publishable_...`). Старый `anon` key тоже подходит. Никогда не используйте в браузере `service_role` или secret key.
5. Впишите URL и publishable key в `config.js`. Публичный ключ предназначен для браузера; безопасность данных обеспечивают политики RLS из `supabase/schema.sql`.
6. В настройках Supabase Auth добавьте адрес GitHub Pages в список разрешённых Redirect URLs, например `https://ВАШ-ЛОГИН.github.io/ВАШ-РЕПОЗИТОРИЙ/`.
7. Отправьте файлы проекта в ветку `main`. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. После этого workflow автоматически опубликует сайт. Если он завершился до включения Pages, откройте вкладку **Actions**, выберите workflow **Deploy static site to GitHub Pages** и нажмите **Run workflow**.

Пока в `config.js` не указаны ключи, приложение запускается в демо-режиме: переписка сохраняется только в текущем браузере. После настройки Supabase сайт автоматически предложит бесплатный гостевой вход.

Если Supabase возвращает `column reference "conversation_id" is ambiguous` при открытии или создании чата, повторно выполните обновлённый `supabase/schema.sql` целиком в SQL Editor: функции создания личных и групповых чатов используют отдельное имя для переменной идентификатора.

## Push-уведомления и история звонков

История звонков и безопасное хранение push-подписок добавлены в `supabase/schema.sql`. Выполните актуальный файл целиком в SQL Editor, чтобы создать новые таблицы, RLS-политики и триггер записи истории звонков. Уже сохранённые сообщения, профили и звонки не удаляются.

Push требуют HTTPS, установленного Service Worker, явного разрешения браузера и Supabase Edge Function. После применения SQL:

1. Сгенерируйте пару VAPID-ключей локально командой `npx web-push generate-vapid-keys`. Публичный ключ добавьте в `config.js` как `pushVapidPublicKey`. Приватный ключ не публикуйте и не добавляйте в репозиторий.
2. В **Supabase → Project Settings → Edge Functions → Secrets** добавьте `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (например, `mailto:ваша-почта@example.com`) и `PUSH_ALLOWED_ORIGIN` со значением `https://t45449395-crypto.github.io`. Не добавляйте `service_role` в `config.js`: Edge Functions получают его из закрытого окружения Supabase.
3. Установите Supabase CLI, выполните `supabase login`, затем из папки проекта выполните `supabase link --project-ref mihxvkeogwwfzokmwqkt` и `supabase functions deploy send-push`. В `supabase/config.toml` для функции включена обязательная проверка JWT.
4. Опубликуйте обновлённый `config.js` через GitHub. В разделе **Звонки** включите уведомления в каждом браузере/устройстве и разрешите уведомления в запросе браузера.

Web Push работает только после этих шагов; одной настройки GitHub Pages недостаточно. Вызов из уведомления открывает приложение и восстанавливает входящий звонок, пока его предложение не старше минуты. История звонков и групповые Web Push требуют повторного выполнения актуального SQL. На iPhone/iPad может потребоваться добавить сайт на экран «Домой» и открыть его как веб-приложение. Если сеть блокирует прямое WebRTC-соединение, отдельно настройте TURN-сервер.

## Возможности и ограничения

- Бесплатный гостевой вход без SMS, телефона, email и пароля; выход из аккаунта.
- Публичный профиль с уникальным именем пользователя. Гостевой аккаунт привязан к данным браузера: если очистить данные сайта, восстановить его нельзя.
- Переход к профилю собеседника из заголовка личного чата по имени или аватару; групповые чаты не ведут на чужой профиль.
- Поиск пользователей, личные диалоги, сохранение сообщений в PostgreSQL и доставка новых сообщений через Supabase Realtime.
- Поиск и вставка эмодзи в поле сообщения, фильтры, поиск по чатам и адаптивный интерфейс.
- Создание групп с участниками из каталога пользователей, общая история сообщений и отображение имён авторов. В демо-режиме группы и сообщения сохраняются только в этом браузере.
- Отдельная адаптивная страница профиля с редактированием данных, публичной ссылкой, коллекцией подарков и отправкой бесплатных виртуальных подарков. В демонстрационном режиме коллекция сохраняется в браузере; с Supabase подарки доступны между аккаунтами.
- Вложения в личных и групповых сообщениях: изображения, видео, аудио, PDF и текстовые файлы размером до 20 МБ. Supabase Storage остаётся приватным; доступ выдаётся короткоживущей подписанной ссылкой только участникам переписки. В демо-режиме удалённая загрузка отключена.
- Аудио- и видеозвонки один на один между вошедшими пользователями на WebRTC. Для установления связи браузеры передают сигналы через Supabase Realtime и получают доступ к камере/микрофону только после разрешения пользователя.
- Отдельная вкладка «Звонки» с историей входящих/исходящих аудио- и видеовызовов и быстрым повторным вызовом.
- Входящие и исходящие аудиопотоки звонка воспроизводятся независимо от видеопотока; при блокировке автовоспроизведения отображается кнопка включения звука собеседника.
- Настраиваемые Web Push для новых сообщений, вложений и входящих звонков (после установки `supabase/functions/send-push` и VAPID-ключей).
- Звуки отправки и получения сообщений, входящего звонка и исходящего вызова. Их можно включить или выключить кнопкой динамика в заголовке; настройка сохраняется в браузере. Для воспроизведения звука браузеру требуется первое взаимодействие со страницей.
- Для настройки внешнего TURN API укажите в `config.js` `iceServersUrl`: HTTPS endpoint принимает POST с bearer-токеном Supabase и возвращает `{ "iceServers": [{ "urls": ["turn:…"], "username": "короткоживущий", "credential": "короткоживущий" }] }`. Endpoint обязан проверять JWT, включить CORS для адреса сайта и выдавать только временные TURN-учётные данные. Если endpoint не указан, браузер использует публичный STUN Google; этого недостаточно в некоторых сетях.
- Premium пока представлен только информационным экраном: покупка и списания отключены, цена и доступность не заявлены. Таблица `user_subscriptions` предназначена для чтения собственного статуса; изменять его может только доверенный сервер оплаты.
- Для звонков в ограниченных сетях понадобится ваш TURN-сервис и небольшой HTTPS endpoint, выдающий временные credentials. Постоянные секреты нельзя публиковать в `config.js`.
- Для групповой связи голосом/видео, восстановления гостевой учётной записи, привязки телефона с SMS и отправки push-уведомлений нужны отдельные серверные сервисы; текущий бесплатный гостевой вход не является восстанавливаемым способом авторизации.
- Оплата не подключена. Для будущей подписки потребуется серверный endpoint оформления платежа, проверка подписей webhook, возвраты/отмена и выдача статуса подписки на сервере. Секреты платёжного провайдера и `service_role` нельзя помещать в GitHub Pages или `config.js`.
- GitHub Pages обслуживает только статические файлы. Реальные группы, звонки, общие сообщения и файлы заработают после настройки Supabase, выполнения схемы и публикации таблиц `messages` и `call_signals` в Supabase Realtime. Используйте сайт по HTTPS (GitHub Pages предоставляет HTTPS).
